# v0.2.11 — 2026-08-24

## Bug Fixes

### OTA endpoint per-platform
El endpoint del updater ahora usa la configuración por plataforma correcta para cada SO. Antes usaba `{{target}}` (triple Rust, p.ej. `x86_64-unknown-linux-gnu`) que no matcheaba los slugs del release-hub (`linux/x86_64`). Ahora:

- **Linux**: `linux/{{arch}}` vía `tauri.conf.json`
- **Windows**: `windows/x86_64` vía `tauri.windows.conf.json`
- **macOS**: `macos/{{arch}}` vía `tauri.macos.conf.json`

El fix es backwards-compatible — la plataforma se detecta en compile-time via `cfg!()` en Rust y se inyecta en el binary.

### Wizard paso 6 — Pantalla en blanco
Fix crítico: al completar el wizard (paso 6), si fallaba el seed de categorías o productos, una excepción no manejada dejaba el overlay `<Presence>` de Motion montado sobre la app, resultando en pantalla en blanco.

- Las funciones `seedCategoriesIfNeeded` y `seedProductsIfNeeded` ahora tienen `try/catch` individual en `useOnboarding.ts`
- El handler `onClick` en `CompleteStep.tsx` ahora es `async` con `try/catch`

### CI: rust-cache desactivado
El workflow `linux-x64-deploy.yml` ya no usa `rust-cache@v2` — el cache reusaba el binary compilado con una versión vieja del Cargo.toml, haciendo que los artifacts publicaran con la versión incorrecta al hub.

## Infrastructure

- Archivo de logging habilitado por defecto (`VITE_LOG_FILE=true`)
- Instrumentación adicional en `thermal-printer.service.ts` y `sqlite-storage-adapter.ts` para facilitar debugging
