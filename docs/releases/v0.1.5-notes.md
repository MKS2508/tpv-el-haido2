# TPV El Haido — Release Notes v0.1.5

> **Tipo**: Patch release — fix de bug crítico del wizard de first-run onboarding.
>
> **Source range**: `v0.1.4..aa94fe0` (1 commit, fix único).
>
> **Fecha**: 2026-08-23.

---

## 🐛 Corrección crítica — wizard de first-run no se disparaba

Los usuarios que instalaban TPV El Haido por primera vez (o tras un wipe del profile WebKit)
veían la app abrir directo a Home/Login **sin pasar por el wizard de configuración inicial**.
El onboarding de 6 pasos (welcome → storage mode → import data → create users → theme → complete)
estaba implementado como código pero **nunca se montaba en el árbol de Solid**.

### Causa raíz (3 bugs concurrentes)

1. **Estructural** — `<Onboarding />` se exportaba desde `src/components/Onboarding/index.tsx`
   pero ningún archivo lo importaba ni lo montaba. El `<OnboardingProvider>` solo vivía anidado
   dentro de `Match activeSection=settings` para dar contexto al botón "Reiniciar wizard" de
   SettingsPanel. Componente huérfano en producción.
2. **Heurística derrotada** — `shouldShowOnboarding()` retornaba `false` cuando `productsCount > 0`.
   Pero `seedProductsIfNeeded()` corría en `App.tsx` mount y auto-sembraba productos desde
   `products.json` ANTES de evaluar la heurística. El "check de datos vacíos" se invalidaba
   siempre.
3. **Persistencia frágil** — el flag `wizard.completed` se guardaba en `localStorage` con la key
   `tpv-onboarding-completed`. No sobrevivía a wipes del profile WebKit.

### Fix aplicado (r9 / `aa94fe0`)

- **Nueva tabla SQLite `app_state(key, value)`** — persistente en `~/.local/share/com.elhaido.tpv/`
- **2 nuevos Tauri commands**: `get_app_state`, `set_app_state` (registrados en `invoke_handler`)
- **Frontend wrapper `useAppState.ts`** con `Result` pattern + `tryCatchAsync`
- **`useOnboarding`** ahora persiste en SQLite con migración one-shot del flag legacy de
  `localStorage` (si v0.1.5 encuentra el flag en localStorage lo copia a DB y lo borra)
- **`shouldShowOnboarding` simplificado** — ahora retorna `forceOnboarding || !onboardingCompleted`
  (sin heurísticas de productsCount/usersCount)
- **`App.tsx` mount top-level** — `<Show when={onboarding.shouldShow() && !appSplash && !licenseSplash}>`
  con `<OnboardingProvider><Onboarding /></OnboardingProvider>` envuelto en `Presence + Motion`
- **`seedProductsIfNeeded` diferido** al `completeOnboarding` del wizard (no corre en mount)

### Out of scope (no tocado)

- Wizard installer (`./tpv-el-haido.AppImage --install`) — TR-19 scope, otro track, tiene un bug
  separado documentado pero no crítico para producción bar (race condition en `currentWindow.label`
  en `main.tsx:202`). Se abordará en v0.1.6 o 0.2.x.
- Per-version wizard (re-disparar en cada upgrade) — descartado explícitamente en r9 (decisión
  Once-per-install). Si un futuro release trae steps nuevos importantes, se libera con reset del
  flag en DB + bump de release notes avisando al usuario.

### Cómo probar (regression test manual)

```bash
# 1. Limpiar estado de prueba
rm -rf ~/.local/share/com.elhaido.tpv/tpv-haido.db
rm -rf ~/.local/share/com.elhaido.tpv/localstorage/
rm -rf ~/.local/share/com.elhaido.tpv/databases/

# 2. Lanzar AppImage
./tpv-haido-0.1.5.AppImage

# 3. Esperado: splash → license splash → WIZARD primer run (6 steps)
# 4. Al completar wizard → Home/POS con seedProducts aplicado
# 5. Cerrar app y relanzar → salta directo a Login (flag persistido en SQLite)
sqlite3 ~/.local/share/com.elhaido.tpv/tpv-haido.db 'SELECT * FROM app_state;'
# → ('wizard.completed', 'true')
```

Si el paso 3 no muestra el wizard, **abrir issue inmediatamente** con log + sha256 del AppImage.
