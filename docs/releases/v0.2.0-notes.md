## 🎨 Highlights — UI/UX Overhaul (M1–M6)

El overhaul cierra 6 milestones cohesionados, cada uno con su ADR propio (r10–r15). El track
se diseñó por capas: tokens primero (M1), luego composition (M2–M5), luego integrity cleanup
(M6) — el orden minimiza retrabajo porque cada capa referencia solo las inferiores.

### Design system v0.2.0 (M1) — ADR r10

- **OKLCH semantic tokens** en `src/styles/tokens.css` (light + dark): `--color-primary`,
  `--color-card`, `--color-muted`, `--color-border`, `--color-ring`, etc. Reemplazan el shadow
  palette HSL disperso en `App.css`.
- **CVA Button** (`src/lib/cva-variants.ts`): variantes `default | destructive | outline |
  secondary | ghost | link` + 6 sizes + `default | sm | lg | icon` heights. Base para todos
  los botones del app (reemplaza 3 implementaciones divergentes en `button.tsx`/`ConfirmPayment
  Dialog.tsx`/`MoonSunSwitch.tsx`).
- **`AnimatedNumber` component** (`src/components/ui/animated-number.tsx`): `MotionOne`
  spring tween para contadores de KPI (Home stats, OrderPanel totals), reemplaza `setInterval`
  hacks previos.
- **4to tema: TPV Amber** (`public/themes/tpv-amber-{dark,light}.css`) — corporativo,
  identidad hosteleria. Se suma a los 3 pre-existentes.

### Splash + Auth shell (M2) — ADR r11

- **`AppSplashScreen`** reemplaza el `loading.tsx` ad-hoc: tres estados visuales
  (`boot → bootstrap → ready`), Kobalt `GlassContainer` con shimmer, dismiss tras
  primer signal `appState.bootstrapped`.
- **`LicenseSplashScreen`** wrapper consistente para los dos modos (trial + online) —
  antes vivían como dos componentes divergentes.
- **Onboarding unificado** (`src/components/Onboarding/index.tsx`): wizard 6 pasos ya
  montable y persistido en SQLite `app_state` (fix de v0.1.5 per r9). WelcomeStep,
  StorageModeStep, ImportDataStep, CreateUsersStep, ThemeStep, CompleteStep — todos
  consumen los nuevos tokens.

### Sidebar + nav responsive (M3) — ADR r12

- **`SideBar` Kobalt `GlassContainer`** con categorías, user chip, theme selector,
  storage mode indicator. `SideBarToggleButton` accesible (R10 aria-label, h-11 w-11 per
  R7).
- **`BottomNavigation` mobile** (`<md`): 5 destinos, large touch targets, themeable.
- **`ModeToggleSolid`** (replace de MoonSunSwitch): h-11 w-11 (R7), estados visuales claros,
  aria-label `Cambiar tema claro/oscuro`.
- **`SectionHeader`** cohesivo (page title, description, action slot) — `AEATInvoices`,
  `Products`, `Customers`, `Settings` ya lo usan.

### Orders flow polish (M4) — ADR r13

- **`NewOrder`** (`src/components/Sections/NewOrder.tsx`): grid products + active order panel,
  touch targets ≥44px, badges stock-state themeable, isolation `isolate` por cada card
  (R3).
- **`OrderPanel`** + **`PaymentModal`** + **`ConfirmPaymentDialog`**: state machine visible
  (idle → editing → paying → confirmed), `GlassContainer` Kobalt para el sheet activo.
- **1420 LOC de CSS legacy removidas** (`src/styles/neworder.css`,
  `optimized-login.css`, `optimized-order-history.css`, `optimized-product-card.css`,
  `touch-optimizations.css`, `tpv-optimizations.css`) — todo migrado a Tailwind 4.1 +
  tokens. Delta `−3029 / +1764` LOC en el commit `0a611d0`.

### Rest sections polish (M5) — ADR r14

- **`Login`** (`src/components/Sections/Login.tsx`): zero CSS legacy, Kobalt `GlassEffect`,
  PIN keypad accesibilidad (aria-pressed, focus visible).
- **`AuditLog`** soporta `OP_META` themeable (tokens `--color-meta-info / success / warn /
  error`), reemplaza colores hardcoded.
- **`AEATInvoices`** + **`Customers`** + **`Products`** + **`SettingsPanel`** + **`Home`**:
  typography + spacing + table density estandarizada.

### Layout-integrity cleanup (M6 extendido) — ADR r15

Lockeado en 4 buckets cohesionados vía `AskUserQuestion` (waxin autorizó opción B). Detalle
operativo en los 4 audit reports `/tmp/v0.2.0-layout-audit-{1,2,3,4}.md`.

**5 P0 layout-integrity blockers** (alto, bloqueaban release):

- **R1** `Home.tsx` + `Customers.tsx`: añadido `min-h-0` en wrappers `flex-col h-full`.
  Sin esto, en pantallas <700px la última card se cortaba.
- **R6** `OrderHistory` + `Customers` tables: `truncate` + `min-w-0` en rows/cells. Items
  con nombre >60 chars ya no rompen el layout horizontal.
- **R9** `transition-all` auditado: 44 ocurrencias → tokens específicos
  (`transition-colors`, `transition-transform`, `transition-opacity`) en 22 archivos.
  Salvo `tabs.tsx` (upstream Kobalt exception documentada).

**7 urgent layout-integrity**:

- **R7** `ModeToggleSolid` 36×36 → **44×44** (h-11 w-11) per WCAG touch target.
- **R10** 9 icon-only buttons con `aria-label` añadido + 2 Card/Row `role=button`
  + `tabIndex=0` + `aria-pressed`.
- **R11** Home stat-cards: `GlassContainer` → `bg-card` plano. Sin esto, el blur
  nested rompía el repaint en drivers i915.
- **R3** 16 archivos con `backdrop-blur` envueltos en `isolate` (z-context fix).
- **R2** `ScreenshotOverlay` z-index 9999 → 55 (z-55 reserved band per design system).
- **stale**: `ProductCard.tsx.bak` deleted (-257 LOC, huérfano desde v0.1.x).

**Polish rubric 13/16** principios cumplidos + 3 partial. ≥12/16 era el close criterion
per ADR r15. Detalle por principio en `/tmp/v0.2.0-layout-audit-4.md`.

### AppImage bundle hygiene — Commit 2 separado

- `icons/square-icon.png` (512×512 RGBA, ya trackeado en `728adae`) añadido al
  `bundle.icon[]`.
- `category: "Office"` (AppImage autogen classification correcta — antes quedaba

- `publisher: "mks2508"`.
- `shortDescription: "TPV para hostelería"`.
- `longDescription` extended en español.
- Fix dock pre-launch icon visible en GNOME + KDE Wayland.

## ✅ Breaking changes

**Ninguno funcional**.

- **Data model**: no migrado. Tablas SQLite, schemas y seeds intactos.
- **IPC commands**: no añadidos ni renombrados. Los 25 commands expuestos siguen disponibles.
- **Tauri capabilities**: no modificadas (`default.json` igual).
- **Rutas de archivos**: todas las imports `@/...` consolidadas; no hay renames
  públicos.
- **License schema / AEAT**: intactos.
- **PWA service worker / manifest**: intactos (PWA scope `/tpv/` y `public/sw.js` no
  tocados).

El overload es estrictamente visual: cambia cómo se ve y se interactúa con las secciones,
no qué hacen. Cualquier usuario que actualice de v0.1.5 → v0.2.0 verá el overhaul
completo sin pérdida de funcionalidad.

## 🧪 Cómo probar (manual)

### Smoke test — overlay visual

```bash
# 1. Backup del profile (idempotente)
mv ~/.local/share/com.elhaido.tpv{,.bak-v0.1.5} 2>/dev/null

# 2. Lanzar el nuevo AppImage (bajo release-hub una vez publicado)
./tpv-el-haido-0.2.0.AppImage
```

### Casos de prueba específicos

1. **Login + Onboarding 6 steps** — arranca con DB limpia, debe mostrar splash → license →
   wizard (welcome → storage mode → import data → create users → theme → complete).
   Al completar debe persistir `wizard.completed=true` en SQLite `app_state`.
2. **Nueva orden (POS hot-path)** — `NewOrder` → seleccionar 5 productos →
   `OrderPanel` debe mostrar totales animados (AnimatedNumber) → `PaymentModal` →
   `ConfirmPaymentDialog` → cierre con animación. Touch targets ≥44px en grid.
3. **Tabla `OrderHistory` con item 60+ chars** — crear orden con producto de nombre largo,
   debe truncar con `...` sin romper el row height (R6).
4. **Tabla `Customers` con email 40+ chars** — idem. Email debe truncar antes de empujar
   la columna `Acciones`.
5. **Dashboard `Home` con 50+ órdenes** — el scroll del KPI grid debe fluir sin
   re-layout (R1 min-h-0 fix); sin esto se cortaba la última card.
6. **Theme switch — 4 disponibles** — `ModeToggleSolid` debe ciclar light → dark → system.
   TPV Amber debe estar disponible en `ThemeSelector` (sumado a Light, Dark, etc.).
   La animación de transición entre temas no debe tener flicker (R9 tokens específicos).
7. **AppImage dock pre-launch icon** — minimizar tras lanzamiento, debe mostrar el icono
   cuadrado (no el default Tauri); abrir desde dock debe restaurar la ventana sin re-splash.

### Regression crítico (no debe romperse)

- License validation (master + online) — `check_license_status`,
  `validate_and_activate_license`.
- AEAT `aeat-bridge` sidecar — arrancar, validar un invoice NIF de prueba.
- Auto-updater — settings → buscar update, debe respetar `https://haido.releases.
  mks2508.systems/api/updates/...` con minisign.
- Storage mode switch sqlite ↔ http ↔ indexeddb — debe persistir en localStorage y
  restaurar al relanzar.
- PWA scope `/tpv/` (no tocado).

## 🚫 Out of scope (deferred a v0.2.1+ o 0.3.0)

Lockeado en ADR r15 explícitamente — lo que **no** entró en v0.2.0:

- **`OP_META` refactor completo** — AuditLog actualmente themeable, pero el type
  `OperationMetadata` en `src/types/audit.ts` aún tiene 8 campos inline; se consolidará
  en discriminated unions en v0.2.1.
- **`SettingsPanel` 11-tab consolidation** — sigue con 11 tabs; rediseño a 4 panes
  + drawer está en track separado (`track/v0.2.1-settings-polish`).
- **`AuditLog` mock data** — el componente renderiza OK pero los datos históricos
  en DB son sample. Integración con `audit_log` table real pendiente.
- **R7 audit completo** — solo arreglamos `ModeToggleSolid` (medido: el más clickado
  en sesión de bar). Quedan ~22 botones potenciales bajo 44px en pages secundarias;
  audit completo en v0.2.1.
- **TS strict mode full** — `tsconfig.json` aún tiene `strict: false`. Track dedicado
  en v0.3.0 (acompaña al multi-platform build hardening).
- **A11y profundo (axe-core)** — solo pasamos R10 (icon-only aria-label) + R7 (touch
  targets). Full audit con `axe` deferred.
- **Dark mode en todas las páginas** — la mayoría soporta dark, pero `AEATInvoices`
  sigue con tabla forzada-light; se verá en polish del track `license-2.x`.
